# CC Notify: Claude Code / Codex 알림 오버레이 (macOS)

VS Code 창을 여러 개 켜두고 Claude Code나 Codex를 돌리다 보면, 어느 창이 허용을 기다리는지 놓쳐서 작업이 한참 멈춰 있곤 합니다. CC Notify는 이 문제를 해결하는 작은 오버레이 앱입니다.

- 세션마다 화면 우측 가장자리에 작은 카드가 붙어 있습니다. Claude Code 세션(터미널, VS Code 확장)과 Codex 세션(CLI, 데스크톱 앱)을 모두 지원합니다.
- 에이전트가 허용을 기다리거나, 질문을 하거나, 작업을 마치면 소리와 함께 보고 있는 화면 테두리가 살짝 번쩍이고, 카드가 펼쳐지며 무슨 일인지 보여줍니다.
- 카드를 클릭하면 해당 세션의 창이 앞으로 나옵니다. 허용과 거부는 그 창에서 직접 결정합니다.

상세 문서: 문제정의와-솔루션.md, 기능-명세.md, 제작-파이프라인.md

## 설치

```bash
npm install
bash scripts/install-hooks.sh
```

install-hooks.sh는 두 곳에 등록합니다.

- Claude Code: `~/.claude/settings.json`에 hook 8개(SessionStart, PreToolUse, PostToolUse, PermissionRequest, UserPromptSubmit, Notification, Stop, SessionEnd)와 플랜 사용량 게이지용 statusline(hooks/statusline.sh). statusline 스크립트는 화면에 아무것도 표시하지 않는 데이터 통로이며, 직접 만든 statusline이 이미 있으면 덮어쓰지 않고 알려만 줍니다.
- Codex CLI: `~/.codex/hooks.json`에 hook 7개(위에서 Notification 제외). `~/.codex` 폴더가 없으면 건너뜁니다.

기존 설정은 보존되고, 쓰기 전에 각각 `.bak`으로 백업됩니다. hook은 새로 시작하는 세션부터 적용됩니다.

Codex는 새로 등록된 hook을 사용자가 한 번 검토, 신뢰해야 실행합니다. 설치 후 codex 대화형 세션 안에서 `/hooks`를 실행해 notify.sh 항목을 신뢰(trust)로 표시하세요. 신뢰 전에는 Codex 세션 카드는 뜨지만(프로세스 스캔) 알림은 오지 않습니다.

## 실행

```bash
npm start
```

메뉴바에 🔔 아이콘으로 상주하고 Dock에는 표시되지 않습니다. 메뉴바 메뉴에서 음소거, 상시 글로우, 로그인 시 자동 시작을 설정할 수 있습니다.

패키징된 앱을 만들려면:

```bash
npm run build
open "dist/mac-arm64/CC Notify.app"
```

## 카드 읽는 법

카드 모양이 에이전트, 카드 색이 상태입니다.

- Claude Code 세션: 둥근 사각형 카드
- Codex 세션: 왼쪽이 둥근 알약(타원) 카드. 접혀 있을 때 보이는 왼쪽 띠도 둥근 끝이라 접힌 채로 구분됩니다

같은 폴더에서 두 에이전트를 함께 돌리면 카드가 2장 뜹니다. 카드 이름에 마우스를 올리면 툴팁 첫 줄에 어느 에이전트인지 적혀 있습니다.

색은 두 에이전트가 같습니다. 파란 계열은 내 차례, 보라는 에이전트 차례라고 기억하면 됩니다.

| 색 | 의미 | 하면 되는 일 |
|---|---|---|
| 주황 | 허용 대기. 어떤 도구를 실행하려는지(bash 명령 전문, 파일 경로 등)가 카드에 표시됩니다 | 카드를 클릭해 창으로 가서 허용 또는 거부 |
| 파랑 | 입력 대기. 작업 중 Claude가 질문을 했습니다 | 카드를 클릭해 창으로 가서 답변 |
| 초록 | 작업 완료. 턴에 걸린 시간이 함께 표시됩니다 | 다음 요청을 보내면 됩니다 |
| 보라 숨쉬기 + 스피너 | 에이전트가 작업 중입니다 | 기다리면 됩니다 |
| 옅은 파랑 | 유휴. 세션이 입력을 기다리며 쉬고 있습니다 | 없음 |

알림이 해소되는 조건:

- 주황과 파랑: 해당 창에서 응답해 도구가 실행되거나 새 입력을 보내면 사라집니다.
- 초록: 해당 세션 창을 앞으로 가져오는 순간(카드 클릭이든 직접 창 전환이든) 확인한 것으로 보고 사라집니다.
- 응답이 없으면 1분 간격으로 최대 5회까지 소리와 번쩍임으로 다시 알려줍니다. 자리를 오래 비워도 소음이 되지 않도록 5회에서 멈춥니다.

## 사용법

- Claude Code나 Codex 세션이 시작되면 카드가 자동으로 생깁니다. 앱보다 먼저 시작된 세션도 10초 간격 프로세스 스캔으로 찾아냅니다. 다만 hook 등록 전에 시작된 세션은 알림이 보장되지 않으므로, 완전한 동작을 원하면 그 세션을 재시작하세요.
- 카드 클릭: 해당 세션의 창이 앞으로 나옵니다. 세션 폴더 이름과 상위 폴더 이름까지 후보로 창 제목을 매칭하므로, 워크스페이스 하위 폴더에서 실행한 세션도 워크스페이스 창을 찾아갑니다. VS Code가 아닌 곳(Claude 데스크톱 앱, iTerm, Terminal)에서 실행한 세션은 해당 앱을 활성화합니다.
- 알림 카드의 ✕ 버튼(마우스를 올리면 우상단에 나타남): 창 전환 없이 알림만 끕니다. 다른 화면을 보던 중 일단 치우고 싶을 때 사용합니다.
- 카드 드래그: 아무 곳이나 잡고 끌어서 세로 위치를 바꿀 수 있고, 위치는 디렉토리별로 저장됩니다. 끄는 동안은 화면 밖까지 따라가고, 놓으면 화면 안으로 돌아옵니다. 카드와 컨트롤 패널은 서로 밀어내며, 아래쪽에 자리가 없으면 위로 밀려 올라가 화면 밖으로 내려가는 항목이 없습니다.
- 카드 우클릭 메뉴: 카드 닫기(세션은 유지), 세션 종료(claude 또는 codex 프로세스와 셸에 종료 신호를 보내 VS Code 터미널 탭까지 닫힘)를 선택할 수 있습니다.
- 지금 보고 있는 창의 세션 카드만 접히지 않고 펼쳐진 채 유지됩니다. 같은 프로젝트를 여러 앱에서 열었으면 앱 출처까지 맞춰 하나만 고르며, 같은 앱 안에서 후보가 여러 개라 활성 탭을 구분할 수 없을 때는 잘못된 카드를 펼치지 않도록 모두 접어 둡니다.
- 4시간 동안 이벤트가 없는 세션 카드는 흐려집니다.
- 한글 폴더 이름은 hook(NFC)과 프로세스 스캔(NFD)의 유니코드 형태가 달라 같은 폴더에 카드가 두 장 생기던 문제를 NFC 통일로 고쳤습니다(2026-09-23). 설정의 카드 위치 키도 첫 실행 때 NFC로 합쳐집니다.
- 같은 폴더에서 세션을 다시 시작하면(/clear, 재실행, VS Code 확장의 새 대화) 새 카드가 생기고, 이전 세션의 카드는 프로세스가 사라진 것이 확인되면 약 30초 안에 정리됩니다. 폴더당 실제로 돌고 있는 세션 프로세스 수만큼만 카드가 유지됩니다.

## Codex 데스크톱 앱

Codex 앱(Codex.app)은 스레드 전부를 app-server 프로세스 하나로 돌려서 프로세스 스캔으로는 세션을 알 수 없습니다. 대신 Codex가 스레드마다 쓰는 세션 기록(`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`)을 감시합니다.

- 첫 줄 session_meta의 originator가 "Codex Desktop" 계열이면 앱 스레드로 보고, cwd로 카드를 만듭니다. CLI 스레드(originator codex-tui)는 hook과 프로세스 스캔이 맡으므로 여기서는 무시합니다.
- 턴마다 기록되는 task_started, task_complete, turn_aborted로 작업 중(보라 숨쉬기), 작업 완료(초록, 소요 시간 포함), 중단을 표시합니다. 완료 알림은 다음 턴을 시작하거나 카드를 클릭하면 사라집니다.
- 카드 클릭은 Codex 앱을 앞으로 가져옵니다. 카드 툴팁의 출처는 "Codex 앱"입니다.
- 마지막 활동이 3시간 지난 스레드와 보관(archive)된 스레드의 카드는 사라집니다. 앱 시작 시 이미 있던 기록은 상태만 복원하고 지난 완료 알림을 다시 울리지 않습니다.
- 우클릭 메뉴의 세션 종료는 앱 스레드에는 뜻이 없어 비활성이며, 앱에서 닫으면 됩니다.

## 컨트롤 패널

기본으로 도크 맨 위에 떠 있는 작은 패널입니다. 배치에서는 카드와 똑같은 항목이라, 카드처럼 잡고 끌어 세로 위치를 바꿀 수 있고(투명도 슬라이더만 제외), 화면 밖에 놓으면 안으로 돌아옵니다. 패널을 끄는 동안에는 카드들이 실시간으로 비켜 줍니다. 패널 중심이 카드 중심을 넘는 순간 그 카드가 반대편으로 옮겨 가고, 놓으면 그 배치가 저장됩니다.

- 화살표를 누르면 모든 카드를 한 번에 펼치거나 접습니다. 사용량 진행 알림으로 패널이 잠깐 튀어나온 상태에서는 화살표가 접기(›)를 가리키고, 누르면 패널만 접힙니다.
- 펼치면 투명도 슬라이더가 나타납니다. 알림이 뜬 카드는 투명도와 무관하게 선명하게 표시됩니다.
- 접힌 상태의 상시 표시: 토글 아래에 세 항목이 위에서부터 쌓입니다. S는 Claude 세션(5시간 창), F는 Fable 모델별 주간, C는 Codex(세션 창 한도가 오는 플랜이면 그것, 아니면 주간, 알약 테두리)입니다. 각 항목은 머리글자와 사용 %가 한 줄, 리셋까지 남은 시간(예: 2h10m, 2d5h)이 다음 줄입니다. 띠 폭은 그대로 26px입니다. Claude 주간 전체는 펼쳤을 때 행으로 봅니다. 마우스를 올리면 정확한 리셋 시각과 마지막 갱신 시각이 툴팁에 나옵니다.
- 펼친 패널의 각 행 아래에는 리셋 날짜와 시각(오늘 14:30, 내일 01:40, 9/25 (금) 01:40 형식)과 남은 시간이 늘 표시됩니다.
- 마지막 값 유지: 마지막으로 받은 사용량은 설정 파일(usageCache)에 저장되어 앱을 다시 켜도 즉시 보이고, 세션이 없거나 조회가 실패해도 지워지지 않습니다. 2시간 넘게 갱신되지 않은 값이나 이전 실행의 저장본은 흐리게 표시되고 툴팁에 "N분 전 갱신" 또는 "이전 실행에서 저장한 값"이 붙습니다. 리셋 시각이 지난 게이지는 0으로 내려갑니다.
- 플랜 사용량 게이지: Claude Code의 /usage 화면과 같은 값(세션, 주간 한도 %)을 보여줍니다. 세션과 주간 수치는 Claude Code의 공식 statusline 기능으로 받으므로 터미널 세션이 활동하는 동안 실시간으로 갱신되고, VS Code 확장의 세션처럼 statusline이 실행되지 않는 경우에는 아래 모델별 조회와 같은 응답에 든 세션과 주간 값으로 채웁니다(statusline이 15분 안에 온 적이 있으면 그쪽 우선). 그리고 모델별 주간 수치(Fable 등)는 비공식 사용량 API를 15~25분 무작위 간격(시간당 최대 3회)으로 조회해 함께 표시합니다. 접힌 상태에서도 세션 %는 항상 보입니다. 사용량이 일정 단위(세션 5%, 주간과 모델별 10%)를 넘을 때마다 패널이 잠깐 펼쳐지며 알려주고, 80%와 95%를 넘을 때는 소리와 테두리 번쩍임으로 알립니다. 모델별 수치는 조회가 실패해도 마지막 값이 유지되며(흐리게 표시), 나머지 표시에는 영향이 없습니다. 조회가 사용량 API의 호출 제한(429)에 걸리면 그날은 조회를 멈추고 다음날 0시에 자동 재개합니다 (앱을 껐다 켜도 유지).
- Codex 사용량: Codex CLI가 세션 기록(`~/.codex/sessions/.../rollout-*.jsonl`)에 턴마다 남기는 rate_limits(5시간 세션, 주간)를 읽어 같은 패널에 "Codex" 제목 아래 표시합니다. 한 세션 안에 한도 버킷(limit_id)이 다른 줄이 섞여 오고 그중 창 정보가 비어 있는 줄(primary, secondary가 null)이 있어서, 창 정보가 있는 가장 최근 줄을 씁니다 (codex-cli 0.155 실측). 플랜 이름(plus, prolite 등)은 툴팁에 나옵니다. API 호출 없이 파일만 읽으므로 안전하고, Codex 세션이 활동하는 동안 갱신됩니다 (폴더 변경 감지 + 30초 폴링). 플랜에 따라 세션 또는 주간 중 하나만 올 수 있습니다. 접힌 상태에서는 Claude 세션 % 아래에 Codex 첫 한도 %가 알약 테두리로 표시됩니다. 계단과 임계 알림 정책은 Claude와 같습니다.

## 권한

카드 클릭으로 창을 앞으로 가져오는 기능은 macOS 손쉬운 사용(접근성) 권한이 필요합니다. 첫 클릭 시 시스템이 권한을 요청하며, 시스템 설정의 개인정보 보호 및 보안, 손쉬운 사용에서 이 앱(개발 실행 시 Electron)을 허용하면 됩니다.

## 주의사항과 한계

- 창 매칭은 창 제목에 세션 폴더(또는 상위 폴더) 이름이 포함되는지로 판단합니다. 같은 폴더 이름의 프로젝트가 여러 개 열려 있으면 다른 창이 선택될 수 있습니다.
- 이 앱은 알림 전용입니다. 허용과 거부 입력은 항상 해당 창에서 직접 합니다.
- 세션 종료는 SIGTERM을 보내는 방식이라 진행 중이던 작업이 그 자리에서 중단되며 되돌릴 수 없습니다.
- Claude Code가 내부적으로 띄우는 백그라운드 데몬(claude daemon run, bg-pty-host)은 창이 없는 보조 프로세스라 세션으로 취급하지 않습니다. VS Code가 업데이트로 재시작될 때 이런 데몬이 고아로 남아도 유령 카드가 생기지 않습니다.
- Codex 데스크톱 앱 스레드는 프로세스가 아니라 세션 기록 파일로 감지합니다(아래 참고). 앱에서 허용 요청 다이얼로그가 뜨는 것은 기록 파일에 남지 않으므로, `~/.codex/hooks.json`의 hook이 앱 세션에서도 실행될 때만 허용 알림이 옵니다 (앱에서 hook 실행 여부는 아직 실측하지 못했습니다). codex의 비대화형 하위 명령(exec, review 등)과 앱이 띄우는 app-server 프로세스는 스캔에서 세션으로 잡지 않습니다.
- Codex hook은 사용자가 `/hooks`로 신뢰하기 전에는 실행되지 않습니다 (Codex의 안전 장치). 신뢰 전에는 카드만 뜨고 알림이 오지 않습니다.

## 진단 로그

재현이 드문 문제(접기 버튼이 듣지 않는 현상 등)의 단서를 `~/Library/Application Support/claude-code-notification/diag.log`에 남깁니다 (512KB를 넘으면 diag.log.1로 한 번 돌림). 기록되는 것:

- ctrl toggle: 접기/펼치기 클릭 전후의 패널 상태(클래스, 실제 translateX, 진행 중 애니메이션)와 카드별로 펼쳐져 있는 이유(allOut, alert, front, settling, hover, drag)
- collapse stuck: 클릭 뒤 전환이 끝났어야 할 시점에 접혀야 하는 패널이나 카드가 여전히 펼쳐져 있으면 그 순간의 상태 전체
- card css-hover-mismatch: CSS :hover는 켜져 있는데 앱이 추적하는 hover는 꺼진 경우 (커서가 창 밖으로 나갈 때 hover가 고착되는 의심 사례)
- ctrl pulse start/end: 사용량 진행 알림으로 패널이 펼쳐지고 접힌 시각
- usage: Codex 기록에서 창 정보가 빈 줄을 건너뛴 횟수, 모델별 조회 실패 사유

접기 문제가 다시 생기면 그 시각 전후의 diag.log를 보면 됩니다. 지금 이 순간의 카드 목록(세션 ID, 마지막 이벤트 경과, 스캔 확인 여부)과 사용량 상태는 `curl http://127.0.0.1:48923/state`로 볼 수 있습니다.

## 제거

3. `~/.codex/hooks.json`에서 notify.sh가 포함된 항목을 모두 삭제 (또는 백업 hooks.json.bak으로 복원).
